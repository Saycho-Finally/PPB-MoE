## 一、O2：失败分类学对照（Self-Healing Agentic Orchestrators，arXiv 2606.01416）

已核实。作者 Rahul Suresh Babu、Adarsh Agrawal（独立研究者 / IEEE 高级会员），
2026-05-31 提交。**把可靠性当作有界运行时控制问题**：故障信号 → 失败类别 →
预算内定向恢复 → 轨迹验证 → 可观测性记录。

论文列举的编排层故障形态（与待办清单 O2 所引一致）：
**工具超时 / 参数畸形 / 陈旧上下文 / 证据矛盾 / 重试环 / 未验证中间输出**。

关键数字（100 任务故障注入基准）：自愈 98.8% 对 retry-only 94.5%、全量重规划 93.8%；
单次恢复预算下差距最大：**94.0% 对 85.3% 与 88.2%**；受控语义静默失败场景中，
**验证器引导的自愈把静默失败降到 0.0%**，非验证基线更多返回"看似合理但错误"的输出。

**第三方评审（Pith）的保留意见，引用时应一并记录**：
"核心增益建立在一个**未经验证的分类步骤**上，而基准可能就是按这套分类调的"
（the headline gains rest on an unvalidated classification step that the benchmark
may have been tuned for）。

### 与本仓库 CognitiveMonitor 的逐类对照

| 论文故障类 | 本仓库监控项 | 状态 |
|---|---|---|
| 重试环（retry loops） | 循环耗尽告警 | 已覆盖 |
| 工具超时 / 参数畸形 | 工具错误率 | 部分覆盖（错误率有，超时未单列） |
| **未验证中间输出** | **静默失败检测（0.3.0 新增）** | 结构性子集已覆盖；语义级需验证器 |
| **陈旧上下文（stale context）** | 无 | **缺口** |
| **证据矛盾（contradictory evidence）** | 无 | **缺口** |
| token 速率 / 路由健康 | （论文无对应类，属我们的编排侧） | 我们独有 |

**结论（O2 的答案）**：分类学补全后，本仓库的缺口是**陈旧上下文**与**证据矛盾**两类
——它们都需要跨步骤的状态/语义判断，超出确定性监控的范围，如实记为缺口而非实现。
我们的独有项（token 速率、路由健康、bias 回灌）在论文中无对应物，属编排层贡献。

## 二、O3 补充：静默失败检测在业界实践中的位置

本轮检索发现静默失败已是 2026 年的显式工程话题，业界实践与本仓库四条规则同向：

- **零输出 token**（input>0 而 output==0）是最常用的确定性信号；输出摘要为空或
  出现占位串（如"[No response]"）紧随其后——与我们的 `empty_output` / `placeholder`
  两类一致
- n1n.ai（2026-08）统计工具调用在生产中 3%-15% 会失败，其中静默类（HTTP 200 + 空
  payload）最危险；建议"输出边界做严格 schema 校验、把空 payload 当显式异常"
- 也有把"成功率"重定义为"非空且非幻觉结果的比例"的声音——与本仓库把静默失败与
  显式失败**分开记账**的动机一致
- ** Singh et al.（2026）的批评必须写进我们的局限**：输出检查分不清
  "空是因为没发生"与"空是因为工具选择不报"——这需要**接口契约**而非输出检查；
  自愈论文的验证器引导方案（语义级）正是更高一档

定位结论：本仓库的四条规则是**零成本确定性第一档**；语义级静默失败需要验证器或
模型参与（Self-Healing 用验证器把静默失败压到 0.0%）。这与"判定器光谱"同构：
确定性档在前，生成式档在后，按预算升档。

## 三、O4：在线学习表述核对（结论：必须区分作用层）

**Auxiliary-Loss-Free Load Balancing**（Wang et al., DeepSeek, arXiv 2408.15664，
2024-08）是"规则式 bias 负反馈"的出处：每个训练步按专家负载更新 bias
（过载减 γ、饿死加 γ），bias 只参与 Top-K 选择、不参与 gating 计算，
**推理时 bias 通常被吸收进 router 权重**。已被 DeepSeek V3/R1、Kimi K2、GLM-5 等
2026 年主流开源 MoE 采用；2026-12 的理论工作（arXiv 2512.03915）把 ALF-LB 形式化为
原始-对偶方法并给出对数期望遗憾界。

**本仓库 `rebalance()` 的定位必须这样写**：

- 机制**同形**（过载降权、饿死升权的规则式负反馈），**作用层不同**——
  ALF-LB 是训练时机制（服务于梯度训练的负载均衡），本仓库是**服务运行时**的
  观测回灌（不触碰模型权重，只改路由 bias，用于在线的负载整形与饿死恢复）
- **不声称提出该机制**；引用 ALF-LB 作为机制出处的训练时对应物
- 本仓库在线学习**未做**（当前是"执行后调整"），此表述不变；
  与 auxiliary-loss-free 结论再核对的结果是：没有发现"运行时 bias 回灌"与
  "在线学习"被混用的公开工作，我们的表述（两者是不同的事）保持成立
- 参数对照：ALF-LB 的 γ 跨 1B-671B 规模几乎不用调；我们的步长 0.05 / 阈值 50%
  是**启发式初值、未调参**——这一句必须保留，不能借 ALF-LB 的跨规模稳定性背书自己
