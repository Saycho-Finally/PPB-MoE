## 二、端到端接线（`orchestration_demo.py`）

复合任务分解为 6 个子任务，全部按能力路由分派：

| 子任务 | 所需能力 | 路由结果 |
|---|---|---|
| 用户偏好变化入场 | remember | memory |
| 报表数字核对（采样） | solve | sampler |
| 数值验证 | verify | verifier |
| 会话前缀编排 | prefix_orchestration | cache |
| 内容门核证 | knowledge_gate | knowledge |
| 视觉任务（无专家） | vision | 无（清晰失败） |

结果：5/6 命中专家，第 6 项按设计返回 no expert；成功率 0.833；路由熵 2.3219。

**一处已修复的缺陷**：记忆专家在早期版本中因对决策核的错误导入而注册失败
（本应注册 5 个专家，实际只注册 4 个），失败被 `except ImportError` 静默吞掉。
该缺陷已于 2026-10-05 修复——决策核为可选注入，缺失时不应阻断专家注册。
修复后五专家全部注册，路由熵由 2.0（4 专家）升至 2.3219（5 专家）。

## 三、静默失败检测（v0.3 新增维度）

**动机**：原有四项监控（token 速率 / 循环耗尽 / 工具错误率 / 路由健康）都只看
"失败有没有被报出来"。而可靠性控制平面方向的工作指出，更危险的是**语义静默失败**：
调用返回成功，产出却不可用——聚合指标显示一切正常，实际什么都没做成。

**实现**：四类确定性规则，纯离线可复现。

| 规则 | 判据 |
|---|---|
| `empty_output` | 报成功但产出为 `None` / `""` / `{}` / `[]` |
| `degraded_note` | 只有说明性字段（`note` / `degraded` / `fallback` / `orchestrated` …），无实质产出 |
| `placeholder` | 产出含占位标记词（词表见代码中的 `PLACEHOLDER_MARKERS`） |
| `no_op_echo` | 产出与输入相同（无变换） |

**记账口径**：显式失败（`ok=False`）抬高工具错误率；静默失败抬高 `silent_rate`。
两者分开记账，因为处置不同——前者重试或换工具，后者要查"为什么报成功"。

### 检测器抓到的第一个真实问题

演示脚本的缓存专家原本写的是：

```python
from cachecortex.prefix_bank import PrefixBank     # 该符号不存在
```

正确的类名是 `PrefixBankSession`。导入失败被宽泛的 `except` 吞掉，于是它返回
`{"orchestrated": True, "note": "prefix append-only 纪律就位"}`——
**`ok=True`，成功计数照加，但缓存层实际上什么都没验证**。这正是静默失败的定义。

修正为 `PrefixBankSession` 后，改为离线验证前缀**字节稳定性**（同配置的两个会话，
`prefix_fingerprint` 与 `log_fingerprint` 必须一致）。这是能离线验证的那部分纪律；
命中率需要真实 provider，离线测不出来，不在本项声称范围内。

结果：演示脚本 `silent_rate` 由 **0.2 降为 0.0**，而 `success_rate` 保持 0.833 不变。
即：**旧指标看不出差别，新指标看得出来。**

## 四、口径与局限

- 偏置步长（0.05）与过载阈值（50%）为启发式初值，未做大样本调参
- 观测回灌为"执行后调整"，未做在线学习
- 第 9 项为**人为设定偏置**后的路由检验，用于验证回路可达性，
  不代表自然收敛后的分布
- 组件粒度审计的三维统计依赖被测目录树；目录结构变化后需重测
  （本仓库已按当前目录树重测，早期记录中的复用计数已相应更新）
